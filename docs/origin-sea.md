# 始源星海背景测试

适用：Minecraft 1.21.1 / NeoForge。进入主世界后在聊天栏输入：

```text
/originsea on
```

深蓝星云、细密星点、青蓝云海、头顶粉紫色破碎天幕和旋转下落的碎片
都会替换当前客户端的天空。白天、夜晚及天气不会改变这套背景。
朝不同方向转动、抬头可以观察完整的 360° 天幕。

| 命令 | 用途 |
| --- | --- |
| `/originsea` | 切换背景 |
| `/originsea on` / `/originsea off` | 开启 / 关闭并恢复原版天空 |
| `/originsea floor on` | 在当前脚下高度开启纯视觉海面 |
| `/originsea floor off` | 关闭额外海面，保留天空 |
| `/originsea floor height 64` | 将视觉海面固定在 Y=64 |
| `/originsea shards 1600` | 调整碎片数量，范围 0–3200，默认 1600 |
| `/originsea status` | 查看当前开关、海面和碎片数量 |

这些是客户端命令，不需要作弊权限，也不会发送服务器命令。设置仅在本次连接
有效，退出世界后复位；切换到下界或末地时暂停生效，返回主世界恢复。

## 看图建议

先在开阔地看天空。要观察参考图那种无边际镜面，建议使用创造模式的虚空测试
世界，站在小平台上执行 `/originsea floor on`。海面高度会固定，不跟随玩家
上下移动；它没有碰撞，不能承载玩家。原有山体、建筑和实体仍按深度正常显示。
天空下半球也有云海倒影，因此站在虚空中即使不启用额外海面也可以看到背景。

海面反射的是星海环境，不包含玩家、建筑或其他实体的实时镜像。
碎片只是远景网格，没有实体、碰撞、掉落物、粒子实体或服务器 tick。
水下、岩浆、细雪、失明和黑暗效果继续使用原版视觉遮挡。

## 实现与边界

- `client/originsea` 使用 NeoForge 的 `DimensionSpecialEffects` 天空、云和天气钩子，
  以及 `AFTER_SKY` 海面渲染事件；无需 Mixin 或外部光影包。
- `assets/lyycore/shaders/core/origin_*` 使用 GLSL 150 程序生成星云和裂口，
  按用户提供的六张截图重建配色与构图，没有把角色或 UI 烘焙进背景。
- 六张图作为同一大缺口的不同朝向参考：整圈轮廓和局部伸入开口的残壳
  定义在 `shaders/include/origin_firmament.glsl`，天空和碎片共用，转动视角时
  保持连贯。它是根据截图重建的形状，不是原作场景模型的直接导入。
- 碎片数量仍默认 1600，其中 60% 是缺口边缘常驻的破碎天幕，位置固定、仅轻微
  摇动，不下落或重生；多层不规则轮廓及透光间隙保持裂口的破碎感。其余 40% 是
  已脱离的小碎片，缓慢下坠并翻转，周期 12–20 秒；下落距离按出生高度限制，
  在高空淡出，不落向地面。
  网格只上传一次，GPU 计算运动；暂停游戏时动画暂停。关闭背景、退出世界或
  资源重载时释放 GPU 网格。
- 天空与碎片使用无行走/受伤摇晃的投影，保留转头和世界视野缩放，不随玩家平移
  产生近景视差。额外视觉海面仍使用世界投影，以维持与地形的深度遮挡关系。
- 替换主世界效果注册项。若另一模组覆盖同一注册项，命令会报告不可用。
  第三方光影包可能接管天空，需要单独验证兼容性。
- 默认关闭，不增加配方、物品、维度或服务器游戏机制。

构建：`./gradlew.bat build --console=plain`。

## 可重复渲染检查

```powershell
.\gradlew.bat -I tools/origin-sea-check/init.gradle runOriginSeaCheck --console=plain
```

该检查会启动独立的开发客户端，在 `build/origin-sea-check/run` 创建虚空测试存档，
自动拍摄六个朝向、仰视、动画两帧、视觉海面及关闭后的画面，验证命令、失明/黑暗
遮挡、资源重载和极佳画质模式后退出。结果和截图位于 `build/origin-sea-check`。
另外用实际顶点 shader 的 GPU 输出检查全部 3200 个碎片：边缘块位置固定，脱落
碎片下坠、翻转且保持在高空；逐像素比较
同视角带/不带摇晃的天空，检查转头、FOV 和相机平移，并输出 4 秒动画序列至
`motion-frames`；结果记录在 `motion-result.txt`。
两根石英柱作为前景遮挡检查物，仅出现在这个测试存档。
检查类仅由这个 Gradle 初始化脚本加入，正常构建的模组不包含测试入口。
运行检查后再执行普通 `build`，即可得到不含检查类的发行 JAR。
